# V2.18 下载进度复查（2026-11-11）

## 变更与原因

并发分段原先只在整段成功后累计 `completed`，大文件/慢网会在分段完成前长时间没有百分比变化。现在在每次成功写入之后报告该段的累计字节，使用每段 high-water mark 汇总。相同段重试不会再次计入已写入的偏移；`completed` 仍独立用于确认所有段均完整且通过响应校验。

进度回调串行化，整数百分比去重，传输中封顶 99%；只有所有分段成功、文件关闭成功后才报告 100%。原有整流回退的百分比单调策略保留。

## 复查轮次

1. 扩展专项测试：3–64 每个线程数都在所有分段首块后暂停，验证首段完成前已报告中间进度，并通过 UI 队列读取原生进度条位置。检查进度严格递增、最终 100%、拼接内容逐字节一致。
2. 扩展写入和集成验证：短写/写入出错只计入实际成功写入的字节；重试到相同偏移不增加百分比；真实有效 ZIP 经 `getLatestPackage`、进度回调、UI 队列、状态文字及原生进度条完整联通。专项与已有回退测试连续 3 轮通过。
3. 完整竞态回归连续 3 轮通过；再以随机顺序运行完整竞态回归 3 轮，检查全局原生窗口/配置状态之间的相互影响。`go vet ./...`、`git diff --check` 和正式构建通过。

复查未发现本次已知长度下载进度变更的新增运行逻辑问题；补充了上述回归覆盖。该结论不代表对所有环境或未测试行为作无缺陷保证。

## 边界说明

- 主进度条仍表示当前阶段，不是整个多目标安装事务的加权总百分比；解压等阶段沿用原来的进度语义。
- 未知 Content-Length 的单流沿用原有完成通知，本次不猜测文件总大小或伪造百分比。
- 慢网下低于 1% 的字节变化不会使整数百分比前进；网络停滞时也不会虚增进度。
- 不改变并发线程范围、下载校验、缓存内容、安装事务或生产运行日志。

本地执行记录、正式构建、源代码补丁和回滚脚本集中在 `dist/release-V2.18/`。发布后以 GitHub Release 元数据、公开下载文件 SHA-256、远端提交与标签、生产文件 SHA-256 交叉确认。
