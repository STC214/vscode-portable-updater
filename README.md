# AutoUpdata VSCode

一个用于 Windows 的便携版 VSCode 自动更新工具。

它会扫描你配置的 VSCode 安装目录，自动识别当前架构与版本，先查询微软官方更新接口并比较版本号，仅在本地版本较旧时下载对应架构的最新稳定版，完成替换升级。

## 功能

- 支持批量配置多个 VSCode 目录
- 单实例运行：同一台电脑仅允许一个更新器实例；重复启动时提示使用已打开的窗口并退出，避免配置和下载缓存冲突
- 自动识别 `x64` 和 `arm64` 版本
- 从官方更新地址下载最新稳定版
- 界面可选 3–64 路 HTTP Range 分段并发下载，默认 16 路，选择后自动保存并在重启后恢复。至少 4 MiB 且服务器提供强 ETag 或满足强校验条件的 Last-Modified 时使用所选并发数；每段最多尝试 3 次，连续 2 分钟无数据则重试，整个下载最多 30 分钟。服务器忽略 Range（包括探测后忽略）、小文件或缺少稳定版本标识时使用单连接
- 分段失败只重试该段；本轮重试耗尽后仍清理临时文件，不支持跨次启动续传
- 自动保留原有 `data` 目录
- 内置进度条和日志窗口，便于查看更新过程
- 配置和缓存都保存在程序旁边的本地目录，适合便携使用

## 使用场景

适合以下情况：

- 你使用的是便携版 VSCode
- 你希望在一个工具里维护多个 VSCode 安装目录
- 你想让更新过程尽量自动化，但仍然保持可见、可控

## 运行前准备

1. Windows 10/11
2. 目标 VSCode 目录中应包含 `Code.exe`
3. 目标目录建议是便携版 VSCode 的根目录，也就是包含 `resources\app\package.json` 的目录

## 使用方法

1. 启动程序
2. 在界面中添加一个或多个 VSCode 路径
   - 在线程设置（第一行按钮后，“下载线程”选择框旁标注 3–64）确认并发数；展开列表时方向键仅预览，Enter 确认、Esc 取消。默认 16，确认后自动保存，更新期间锁定选择，本轮使用启动时的设置
3. 点击“检查并自动更新”
4. 等待程序下载并替换完成

### 路径填写说明

支持两种写法：

- 填写 VSCode 根目录，例如 `D:\Apps\VSCode`
- 填写 `Code.exe` 所在位置，例如 `D:\Apps\VSCode\Code.exe`

程序会自动把 `Code.exe` 路径归一化为其所在目录。

## 工作原理

更新流程大致如下：

1. 读取你填写的安装路径
2. 检查 `Code.exe` 和 `resources\app\package.json`
3. 识别当前版本和架构
4. 查询官方更新接口，获取对应架构的最新稳定版版本号和下载地址（只请求版本信息，不下载 ZIP）
5. 比较版本号：本地版本相同或更高时直接跳过，不下载、不替换
6. 本地版本较旧时才下载更新包，并校验包内版本与查询结果一致；同一批次、同一架构复用下载缓存；跨次运行校验磁盘 ZIP 的版本、架构及所有文件 CRC，通过后复用
7. 解压到临时目录
8. 校验完成后将旧安装重命名为备份，将原有 `data` 以同卷目录重命名迁移到新版，再切换安装目录；原有数据优先于包内数据，不全量复制

版本查询单独设置 30 秒超时，安装包下载保留 30 分钟超时。替换前校验安装结构、可执行文件架构及版本；校验失败时原安装保持不变；数据迁移或目录切换失败时尝试恢复数据和原目录。若回滚也失败，日志记录保留路径，不删除可能包含唯一用户数据的暂存目录。请为临时新版安装预留足够空间；不再需要用户数据的全量副本空间。升级时请关闭 VSCode 及其子进程，迁移期间不要启动。下载前与切换前会检查目录内运行进程，切换前重新核对原版本。更新期间窗口关闭操作会被拦截，完成后即可关闭；配置保存采用串行写入，防止自动保存与立即保存冲突。

## 配置与缓存位置

程序会把配置和缓存放在可执行文件旁边，目录名为：

- `portable_vscode_updater_data`

其中：

- `portable_vscode_updater_data\config.json`：配置文件
- `portable_vscode_updater_data\cache\`：下载缓存
- `portable_vscode_updater_data\logs\YYYY-MM-DD.log`：按天保存带毫秒时间戳的日志，包含查询、下载、解压、数据迁移与切换、旧程序清理耗时

程序启动后还会把临时目录指向同级的缓存目录，避免把临时文件写到系统盘。

配置字段 `download_workers` 保存线程数；旧配置缺少此字段或为 0 时使用默认 16，其他越界整数限制到 3–64。线程越多不保证速度越高，可按网络情况调整。

## 重要限制

- 程序目录位于 `C:` 盘时会直接报错
- 这是为了避免在不能写入 `C:` 盘的前提下，仍然尝试保存配置和缓存
- 建议把程序放到其他盘符的便携目录中运行

## 构建

项目使用 Go 构建，执行下面的 PowerShell 脚本即可：

```powershell
.\build.ps1
```

根目录入口委托给 `scripts\build.ps1`。临时文件和 Go 编译缓存统一放在 `dist\.build\`，不再散落根目录。已有图标资源可直接构建；修改 `assets\app-icon.ico` 后使用 `.\build.ps1 -RegenerateIcon` 重新生成资源（需要 `rsrc.exe`）。可通过 `-OutputPath` 指定其他构建输出位置。

构建完成后，生成的可执行文件会输出到：

- `dist\vscode-portable-updater.exe`

同时，`dist/` 目录也适合作为发布目录，把所有构建产物集中管理。

发行附件只包含标准 EXE 和校验文件；运行配置、缓存为本机数据，不纳入版本控制。旧版 `autoupdata_vscode.exe` 已由 `vscode-portable-updater.exe` 取代。

## 项目结构

```text
.
├─ cmd/vscode-portable-updater/  Go 源码、同包测试、Windows .syso 资源
├─ assets/                     图标与原始图片
├─ scripts/                    构建及测试脚本
├─ docs/reviews/                审查记录
├─ dist/                       构建产物、验证记录及 .build 缓存
├─ build.ps1                   保持兼容的根目录构建入口
├─ go.mod
├─ README.md
├─ CHANGELOG.md
└─ .gitignore
```

Go 源码与测试保持同包，未拆分或改写业务逻辑。`main.go` 为入口，`app.go`/`layout.go`/`theme.go` 负责界面，`updater.go`/`download.go` 负责更新与下载。`.syso` 必须放在 Go 包目录参与链接；图标源文件位于 `assets/`。

### 下载器回归测试

```powershell
.\scripts\test.ps1 -Race -Count 3
go vet ./...
go test -run '^$' -fuzz '^FuzzDownloadContentRange$' -fuzztime=20s -parallel=4 ./cmd/vscode-portable-updater
```

测试脚本同样将临时文件和缓存放入 `dist\.build\`。真实网络下载测试默认跳过。显式设置 `UPDATER_TEST_DOWNLOAD_URL`、`UPDATER_TEST_DOWNLOAD_PATH` 和 `UPDATER_TEST_DOWNLOAD_VERSION` 后，运行 `go test -count=1 -v -run '^TestDownload16Official$' ./cmd/vscode-portable-updater`，仅下载并校验 x64 官方 ZIP，不执行安装。测试输出路径也应选择非 C 盘目录。

## 常见问题

### 为什么启动时提示程序目录不能在 C 盘？

因为这个工具会把配置、缓存和临时文件写在程序旁边。如果程序放在 `C:` 根路径或受限目录里，可能无法保证写入成功，所以程序主动拒绝运行。

### 为什么找不到 VSCode 目录？

请确认你添加的是便携版 VSCode 的根目录，并且目录中确实存在：

- `Code.exe`
- `resources\app\package.json`

### 更新会覆盖我的用户数据吗？

不会主动覆盖 `data` 目录。更新时会尽量把旧版本中的 `data` 目录迁移到新版本中。

## 数据与空间

更新器保留整个 `data`，但不会主动清理扩展、WebStorage、历史记录或扩展下载缓存。目录重命名迁移仅优化升级耗时，不会减少现有用户数据体积。目录切换失败有运行时回滚；断电或强制结束进程后应先根据日志保留路径检查原目录、备份和暂存目录，再手动恢复，不要直接删除这些目录。

### 更新中断保护

切换目录前会在目标旁创建 `<目录名>.update-transaction.json` 并刷盘，记录原目录、备份、暂存路径。正常完成或完整回滚后删除。异常或回滚失败时保留记录和可能持有用户数据的目录；后续升级会停止写入并显示这些路径。请先核实并恢复原安装和 `data`，再移走事务记录；不要仅删除记录后直接重试。该机制提供保留与定位，不承诺断电后自动恢复或原子切换。
